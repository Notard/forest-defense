진행 방식

  • 좌표 변환은 Flame 컴포넌트와 분리된 순수 함수(Grid)로 만들어 단위 테스트를 먼저 붙였다. 4단계 배치, 6단계 몬스터 이동이 모두 이 함수를 쓴다
  • 입력은 TapCallbacks(마우스 클릭과 터치 공통)와 PointerMoveCallbacks(마우스 올림)를 쓴다. 터치에는 올림이 없으므로 탭한 칸을 selectedCell로 남겨 눌린 칸이 보이게 했다
  • 카메라가 고정이라 HUD를 따로 뷰포트 레이어에 두지 않고 월드에 우선순위(priority)로 겹쳤다. 화면 흔들림 같은 연출을 넣게 되면 그때 뷰포트로 옮긴다
  • 진행 바를 오른쪽 아래로 옮겼다 (plan.md 2-1에 이유 기록)

검증

  • flutter analyze 문제 없음
  • flutter test 10/10 통과
  • grid_test.dart 7개: 필드 모서리, 칸 경계가 오른쪽·아래 칸에 속하는지, 필드 밖 5곳(둥지·HUD·등장 구역·진행 바·음수), 칸 가운데 좌표, 레인 y, 45칸 전부 center → cellAt 왕복
  • field_test.dart 2개: 800 × 600 위젯 테스트 화면(4:3, 위아래 75px 레터박스)에서 실제로 탭해 칸 3곳이 맞게 선택되는지, HUD·둥지·등장 구역·레터박스를 탭하면 선택이 바뀌지 않는지
  • forest_game_test.dart 1개: 카메라 고정 해상도와 앵커
  • 브라우저(웹 릴리스 빌드)에서 세 비율을 직접 확인, 콘솔 에러 없음
비율 창 크기 레터박스 확인
16:9 1280 × 720 없음 (2, 4) 칸 올림 강조, (3, 6) 칸 클릭 선택
4:3 1024 × 768 위아래 창 크기를 바꾼 뒤에도 강조 위치 유지, (0, 8) 칸 클릭 선택
19.5:9 1560 × 720 양옆 (4, 0) 칸 클릭 선택

발생한 문제와 해결

  1. 테스트에서 game.size가 800 × 600이 아니라 1280 × 720이었다. 고정 해상도 카메라를 쓰면 FlameGame.size가 가상 해상도를 돌려준다. 실제 화면 크기는 canvasSize로 확인하도록 고쳤다
  2. 위젯 테스트가 "Pending timers"로 실패했다. Flame의 탭 인식기(MultiTapGestureRecognizer)가 탭마다 40ms 타이머를 만든다. 탭 뒤에 tester.pump(100ms)로 시간을 흘려 해결했다
  3. 브라우저 크기 흉내를 처음 켰을 때 화면이 2배로 확대돼 보였다. 그 순간 기기 픽셀 비율이 1에서 2로 바뀌었는데 캔버스가 따라가지 않았다. 새로 고침하면 정상이었고, 그 뒤 일반적인 창 크기 변경(16:9 → 4:3 → 19.5:9)은 새로 고침 없이 정상이었다. 실제로는 배율이 다른 모니터로 창을 옮길 때 생길 수 있으므로 9단계에서 다시 확인한다
  4. 브라우저 탭 제목이 로딩 중에 forest_defense로 보인다 (web/index.html의 <title>). 10단계에서 매니페스트를 정리할 때 함께 고친다

2-1. 한글 폰트: Gaegu Bold (2026-10-13)

왜 폰트를 넣는가

웹 빌드(CanvasKit)는 한글 글꼴이 없으면 Google 서버에서 Noto 폰트를 받아와 대신 쓴다. 오프라인 PWA에서는 그 요청이 실패해 한글이 깨지므로 폰트를 게임 안에 넣는다.

결정 경과

순서 내용
1 후보 3종을 실제 게임 문구로 비교하는 font_preview.html을 만들었다
2 라이선스를 google/fonts 저장소의 OFL.txt 원문으로 확인: 셋 다 SIL OFL 1.1. 게임에 넣어 무료·유료 배포 가능, 조건은 라이선스 전문·저작권 표기 동봉과 폰트 단독 판매 금지
3 사용자가 Noto Sans KR을 골랐지만 원본이 10.4 MB라 Gaegu로 바꿨다
4 Gaegu도 굵기당 약 3 MB라는 점을 알리고 방식을 다시 물었다 → Bold 하나, 글자 줄이기로 결정

결과 요약

항목 내용
원본 Gaegu-Bold.ttf 2,893 KB, 글자 2,593개 (google/fonts ofl/gaegu). 저장소에는 넣지 않음
게임용 assets/fonts/Gaegu-Bold.ttf 78 KB, 글자 107개 + assets/fonts/OFL.txt
남긴 글자 lib/ 문자열에 쓰인 한글·기호 + 영문·숫자·기본 기호
스크립트 python tools/subset_font.py <원본 경로> [--all-hangul]
문구 lib/game/strings.dart에 모음. 지금은 숲 지키기, 웨이브 n / m
연결 pubspec fonts: Gaegu (weight 700), GameConfig.fontFamily, HUD 자리에 임시 글자(150, 웨이브 1 / 5)

진행 방식

  • 처음에는 자주 쓰는 한글 2,350자(KS X 1001)를 남기려 했다. 그런데 Gaegu에는 원래 그 2,350자만 들어 있어서 2,893 KB → 2,891 KB로 거의 줄지 않았다. 손글씨라 글자 하나의 윤곽 데이터가 크다(glyf 표가 파일의 99%)
  • 그래서 게임에 실제로 쓰는 글자만 남기도록 바꿨다. 게임 문구는 정해져 있고 바뀌는 것은 숫자뿐이라 이 방식이 맞다. 2,350자가 다시 필요하면 --all-hangul을 쓴다
  • 스크립트는 코드에 쓰인 글자가 원본 폰트에 없으면 멈춘다. 원본 Gaegu에는 ·, …, ★, → 같은 기호와 백틱(`)이 없어서 게임 문구에 쓰면 안 된다
  • 원본 Gaegu에는 예약 폰트 이름(Reserved Font Name)이 없어 줄인 파일도 이름을 Gaegu로 둘 수 있다. 수정하면 무효가 되는 전자 서명 표(DSIG)만 뺐다

검증

  • flutter test 13/13 통과 (font_coverage_test.dart 3개 추가)
  • 영문·숫자(U+0020~007E, 백틱 제외)가 모두 있는지
  • Strings의 문구가 모두 있는지
  • lib/ 아래 모든 .dart 문자열의 한글·기호가 폰트에 있는지. 폰트 파일의 cmap 표를 테스트가 직접 읽는다 (fonttools로 센 107자와 일치)
  • 일부러 title을 숲 지키기 다람쥐로 바꾸자 두 테스트가 실패했고, 되돌린 뒤 통과했다
  • 웹 빌드: FontManifest.json에 Gaegu 등록, 네트워크 요청은 로컬 Gaegu-Bold.ttf 하나뿐(Google 폰트 서버 요청 없음), 화면에 손글씨로 표시 → preview/02-1_font.jpg

발생한 문제와 해결

  1. 2,350자 기준으로는 크기가 줄지 않았다 → 위 "진행 방식"대로 쓰는 글자만 남기는 방식으로 바꿨다
  2. 스크립트 출력이 Windows 콘솔(cp949)에서 깨지고 – 같은 기호에서 멈췄다 → sys.stdout.reconfigure(encoding="utf-8")
  3. 파이썬 3.11에서는 f-string 안에 같은 종류의 따옴표를 쓸 수 없어 문법 오류가 났다 → 변수로 빼서 해결
  4. dart:ui와 flutter/painting.dart의 TextStyle 이름이 겹쳤다 → HUD 파일은 flutter/painting.dart만 쓰도록 정리
  5. 테스트의 정규식을 raw 삼중 따옴표로 쓰다가 문자열이 닫히지 않았다 → 두 raw 문자열을 이어 붙이는 방식으로 바꿨다

Codex 기본 모델(gpt-6.1-sol)이 ChatGPT 계정 로그인에서 지원되지 않아 바로 실패했다. 사용자 설정(~/.codex/config.toml)은 건드리지 않고, 지난 아이콘 작업에서 쓴 gpt-5.6-sol을 gen_art.py에서 -m으로 지정했다 (환경 변수 CODEX_MODEL로 바꿀 수 있음) 2. 첫 결과가 사실적인 붉은 여우였다 (art/rejected/에 보관, git 제외). 로그를 보니 Codex가 "art brief가 없다"며 파일 이름만 보고 그렸다. 발생한 문제와 해결 1. 경계를 눈대중 다각형으로 자르니 머리 볼 털 일부가 꼬리 조각으로 갔다 → 다각형을 픽셀 단위로 맞추는 대신, 떨어져 나온 작은 섬(부위의 2% 미만)을 가장 많이 맞닿은 부위에 넘기는 정리 단계를 넣었다 (2,123픽셀 이동) 2. 불꽃 가운데(253,253,222)가 앞발 크림색(253,247,232)과 거의 같아 색으로 못 나눴다 (211픽셀이 주인 없음) → 채도 높은 주황 테두리를 찾고 그 안쪽을 채우는 방식으로 바꿨다 3. 렌더에서 꼬리의 가려진 채움이 몸통 위로 비쳤다 → EEVEE 반투명(BLENDED) 물체는 원점 거리로 그리는 순서를 정하는데 모든 평면의 원점이 같은 곳이었다. 평면마다 원점을 자기 가운데·자기 깊이에 두어 해결 4. 채움을 앞 부위 모양대로 하니 부위가 돌 때 테두리 없는 흰 띠가 바깥으로 삐져나왔다 → 실루엣을 닫는(closing) 방식은 채움이 거의 없어져(23~74픽셀) 고개를 들면 틈이 생길 상황이라 버리고, 전체 실루엣 바깥 테두리에서 30px 안쪽만 채우도록 했다 5. 쓰러짐에서 몸을 발 기준으로 크게 눕히니 꼬리·등이 바닥 아래로 파고들어 캔버스에서 잘렸다 → 쓰러짐을 "어지럽게 흔들리다 납작하게 주저앉기"로 바꾸고 회전은 작게, 캔버스 아래 여유를 90px 늘렸다 6. 남은 작은 흠: 던진 뒤 앞발 끝에 불꽃 가장자리 점 몇 개, 쓰러짐 마지막에 꼬리 쪽 작은 흰 조각. 게임 크기에서는 안 보이고, 쓰러짐은 게임에서 연기 효과로 덮는다
